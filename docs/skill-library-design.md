# Prompt Hub Skill 库设计与模型执行策略

> 状态：第一版本地收集、固定 Git 提交快照、审核与受控安装已实现；阶段 D/E 安全边界已于 2026-08-29 完成加固。压缩包导入、自动更新和市场能力仍不在范围内。<br>
> 目标：在不破坏现有提示词库和离线优先原则的前提下，增加对 Codex 等工具 Skill 的收集、审核、搜索和受控安装。

## 1. 产品决策

Skill 库作为 Prompt Hub 的第二类资产实现，不单独新建应用，也不把 Skill 当作普通提示词保存。

理由：提示词与 Skill 共享来源、标签、收藏、搜索、审核、备份和本地优先能力；但 Skill 是一个可包含 `SKILL.md`、脚本、参考文件和资源文件的目录，具有文件完整性与执行风险。独立资产模型能复用现有产品能力，同时避免在提示词详情中混入安装、安全和目录状态。

第一版只支持 Codex Skill 目录结构；数据模型预留 `tool_kind`，以后可增加 Claude Code、Cursor 等适配器。不要在第一版做云同步、团队市场、自动更新或未经确认的批量安装。

## 2. 用户流程

```text
本地目录 / Git 仓库 URL / 压缩包
             ↓
      Skill 收件箱（只读预览）
             ↓
  审核 SKILL.md、文件清单、许可证、脚本风险
             ↓
       保存到本地 Skill 库
             ↓
     明确确认后安装到目标目录
             ↓
      已安装状态、版本、路径、备份记录
```

### 2.1 收集与审核

1. 用户选择本地目录、Git 仓库 URL，或本地压缩包。
2. 系统仅复制或读取到隔离的收件箱区域，解析 `SKILL.md` 与文件清单；不执行任何脚本。
3. 系统显示名称、说明、来源、许可证、提交 SHA（如有）、文件哈希、文件大小、脚本类型和风险提示。
4. 用户可标注收藏、分类、适用工具和审核状态，然后保存为 Skill 资产。

### 2.2 安装与更新

1. 用户从已审核的 Skill 详情选择“安装”。
2. 系统展示目标目录、将新增或覆盖的文件，以及是否检测到同名 Skill。
3. 目标已存在时默认取消；用户可选择“另存为新名称”或“创建备份后替换”。
4. 安装前生成可恢复备份，安装后校验 `SKILL.md` 与登记的文件哈希。
5. 更新必须重新进入收件箱审核，不能直接覆盖已安装版本。

实现还必须满足：安装文件成功但数据库登记失败时，自动回滚刚安装的副本并恢复旧备份；只有刚安装内容仍与登记哈希一致时才允许自动删除。固定 Git 导入忽略全局/系统 Git 配置和凭据助手，禁用本地与扩展协议、hooks 与 submodule，且在读取 blob 前校验文件数、单文件大小、总大小和目录深度。

## 3. 数据与文件模型

### 3.1 Skill 资产

| 领域 | 字段 |
| --- | --- |
| 身份 | UUID、名称、slug、简介、`tool_kind`、分类、标签、收藏状态 |
| 来源 | 来源类型、本地路径或仓库 URL、分支/提交 SHA、作者、许可证、收集时间 |
| 内容 | `SKILL.md` 摘要、目录清单、文件哈希、文件大小、资源类型统计 |
| 审核 | `待审核 / 已审核 / 已拒绝 / 风险待确认`、审核备注、审核时间 |
| 安装 | `未安装 / 已安装 / 更新可用 / 安装失效`、安装路径、已安装哈希、备份路径、安装时间 |
| 使用 | 最后查看时间、打开次数、安装次数、备注 |

`SKILL.md` 正文和其他文本文件在本机保存并以纯文本显示；不得在日志、错误报告或搜索遥测中输出完整内容。

### 3.2 文件安全规则

- 导入只接受本地受控读取、HTTPS Git 仓库或本地压缩包；拒绝 `file://` 以外的未知协议、内网地址和包含凭据的 URL。
- 不解压符号链接到收集目录之外的文件；限制目录层级、单文件大小、总大小和文件数。
- `scripts/`、`.ps1`、`.bat`、`.cmd`、`.sh`、`.py`、`.js`、二进制文件和隐藏文件必须单独列出并提示风险。
- 收集、预览、搜索与元数据编辑阶段绝不运行脚本；“安装”只复制经过确认的文件，仍不运行脚本。
- 不自动安装、不自动更新、不自动覆盖、不自动删除。

## 4. 信息架构与界面

左侧导航新增“Skill 库”，其下使用状态筛选：全部、已安装、待审核、收藏、风险待确认。提示词库与 Skill 库各自拥有详情页，但共享搜索框、收件箱、收藏、来源展示、备份和诊断入口。

Skill 列表以紧凑行展示：名称、适用工具、来源、审核状态、安装状态、收藏星标和更新时间。详情页以 `SKILL.md` 内容为主，右侧显示来源、文件统计、风险、许可证、版本和安装操作。安装按钮仅在审核通过后出现；涉及冲突时使用确认对话框而不是静默操作。

## 5. 分阶段实施

| 阶段 | 交付内容 | 推荐模型与强度 |
| --- | --- | --- |
| A：规格与威胁建模 | 明确资产边界、文件限制、安装/更新/卸载策略、迁移设计 | **GPT-5.6 Sol · xhigh** |
| B：本地只读收集 | 数据表、迁移、目录扫描、`SKILL.md` 解析、风险分类、测试 | **GPT-5.6 Sol · xhigh**（设计与审核）；**Terra · high**（按已定规格实现） |
| C：收件箱与 Skill 库界面 | 列表、详情、审核状态、搜索、收藏、来源与文件清单 | **GPT-5.6 Terra · high** |
| D：受控安装 | 目标路径选择、冲突处理、备份、哈希校验、恢复、端到端测试 | **GPT-5.6 Sol · xhigh** |
| E：Git 导入与更新候选 | HTTPS 拉取、提交固定、差异预览、重新审核 | **GPT-5.6 Sol · xhigh**（安全边界）；**Terra · high**（实现） |
| F：整理与维护 | 文档、测试样本、导入清单、UI 微调、可重复验证 | **GPT-5.6 Terra · medium** |
| G：批量候选整理 | 去重候选、标签建议、来源清单生成；不做最终写入 | **GPT-5.6 Luna · medium**，完成后由 Terra/Sol 审查 |

上述模型分配遵循“高风险决策由最高推理强度处理、明确边界内的实现由 Terra 处理、批量但非权威工作由 Luna 处理”。官方模型指南将 GPT-5.6 Sol 定位为复杂推理与编码首选，将 Terra 定位为能力与成本平衡，将 Luna 定位为成本敏感的高吞吐任务；实际可选模型以当前 Codex 工作区显示为准。[OpenAI Models](https://developers.openai.com/api/docs/models)

## 6. 验收标准

1. 扫描本地目录或导入候选时，不执行任何外部代码。
2. 每个 Skill 都能追溯来源、版本/提交、文件清单、哈希、审核和安装状态。
3. 同名安装冲突默认不覆盖；替换必须先成功创建并验证备份。
4. 失败的导入、安装或恢复不会损坏现有已安装 Skill 或提示词数据库。
5. 已安装 Skill 可通过文件哈希发现本地漂移；检测只读，不自动修复或覆盖。
6. 全部核心流程在无网络、无模型凭据条件下可完成本地部分。

## 7. 当前不做

- 自动执行或测试未知 Skill 的脚本。
- 从 GitHub 自动订阅、自动升级或自动安装。
- 云同步、多人协作、公共市场和评价体系。
- 将 Skill 直接作为 MCP 写操作的目标。
- 把 Skill 文件内容发送到外部模型进行默认分析。

## 8. 开始实现前的检查清单

- 先把本设计的范围并入产品规格，并制定独立实现计划。
- 为每个数据库变更新增前向迁移与迁移测试。
- 为路径遍历、压缩包炸弹、符号链接、二进制文件、脚本文件、同名冲突和恢复失败创建安全测试。
- 先完成 A 阶段的威胁建模与用户确认，再进入 B 阶段。
