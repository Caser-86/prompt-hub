# 永久清除提示词设计

## 目标

为 Prompt Hub 提供受控、可审计的永久清除维护流程，同时保留软删除作为日常可恢复操作。

## 范围与边界

- 只有状态为 `deleted` 的提示词可以永久清除；收件箱、已发布和已归档提示词必须先软删除。
- 永久清除只能从桌面端“维护”界面发起，不通过 AI、MCP 或批量普通操作暴露。
- 每次清除前必须创建并验证 `PermanentDelete` 时间戳备份；备份失败时不修改数据库。
- 用户必须在明确说明不可恢复影响的对话框中二次确认。
- 清除后，提示词实体、所有版本、来源、兼容性、验证、收藏、审计事件和全文索引记录均从本机数据库移除。
- 导入任务记录不保存提示词正文，且不因清除而删除；其 `prompt_id` 外键设为 `NULL`，保留导入审计线索。

## 架构

`prompt-store` 新增仓储级永久清除操作，并在单个事务中删除与提示词 ID 关联的数据。该操作拒绝非软删除状态，以保证所有入口共享同一安全边界。

桌面端 `PromptService` 先通过 `BackupService` 创建经完整性验证的 `PermanentDelete` 备份，再调用仓储操作。Tauri 命令只接受提示词 ID，不允许调用方控制状态或跳过备份。前端维护区仅在当前选中项为 `deleted` 时呈现按钮，并需要输入提示词标题确认。

## 数据流与错误处理

1. 用户在软删除提示词详情中选择“永久清除”。
2. 前端显示不可逆说明，要求输入完整标题；不匹配时禁用确认。
3. Tauri 命令创建 `permanent-delete` 备份并验证 SQLite 元数据。
4. 仓储事务重新读取提示词状态；不是 `deleted` 则返回可读错误且不删除任何数据。
5. 事务清理搜索索引和全部关联表记录，再删除提示词主记录。
6. UI 显示备份路径与成功消息，并刷新列表；任何失败保留当前提示词和 UI 可恢复状态。

不会在错误、诊断或审计显示中记录提示词正文或密钥。

## 验证

- 仓储测试验证非软删除拒绝、关联数据清除、导入任务保留以及事务失败回滚。
- 桌面服务测试验证先备份后清除，且备份失败不会调用仓储删除。
- 前端测试验证仅软删除项显示维护入口、标题确认门槛和成功后的刷新。
- 运行既有迁移、备份、桌面工作流和全量 Session B 验证命令。
