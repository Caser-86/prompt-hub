# Prompt Hub 专业桌面界面重设计

## 目标

将 Prompt Hub 从浏览器默认样式状态改造成可长期日常使用的本地提示词管理工具。界面应优先支持“快速找到、判断、打开和复用提示词”，不改变现有离线、本地优先、收件箱与发布安全边界。

## 已确认的视觉方向

采用专业工具型界面：深石墨侧栏、暖白工作区、靛蓝主操作色、低饱和状态色。整体感受参考成熟生产力工具的克制、高信息密度与明显操作层级，而不复制任何特定产品的品牌元素。

## 范围

### 基础与布局

- 在前端入口显式加载全局样式。当前 `styles.css` 未被 `main.tsx` 导入，导致应用呈现浏览器默认样式；这是首先修复的可观察缺陷。
- 使用固定左侧导航、顶部命令搜索和单一主内容区。小屏时侧栏退化为可横向滚动的导航条。
- 统一按钮、输入框、标签、卡片、空状态、焦点环、对话框和通知的视觉 token；保留键盘可达性和已有 ARIA 标签。

### 提示词库

- 顶部使用紧凑标题和操作区，`创建提示词` 是唯一主按钮。
- 空库不展示空白页面：展示简洁的说明、创建动作与收件箱入口。
- 有数据时使用信息紧凑的卡片列表：标题、摘要、来源、工具/模型、有效性、评分、更新时间、收藏和选择操作按稳定顺序呈现。
- 筛选与批量操作保持现有行为，仅重组为清晰工具栏；不新增数据字段或后端命令。

### 详情、搜索、收件箱和设置

- 详情页将正文置于阅读主栏，来源、兼容性、有效性和时间置于次级信息面板；版本、复制、归档等现有操作按危险程度分组。
- 搜索结果沿用同一张卡片语言，使搜索和库页面有一致的扫描节奏。
- 收件箱强调“草稿待审核”状态；设置按 AI、MCP、备份恢复、诊断分区，降低长表单的认知负担。
- 所有改动仅改变展示层和组件结构，不改变提示词正文、来源、凭据、发布与恢复逻辑。

## 交互与状态

- `Ctrl/Cmd + K` 一直打开命令面板；顶部搜索触发器明确展示该快捷键。
- 鼠标悬停、键盘焦点、禁用、加载、失败与空状态均有可见反馈，且不能只依赖颜色表达状态。
- 卡片中的收藏、选择、打开操作有稳定的命中区，防止点击一个操作意外打开详情。

## 可访问性与响应式

- 保留所有已有语义元素、可见焦点和屏幕阅读器名称；新装饰图标必须 `aria-hidden`。
- 文本与背景符合正常文本至少 4.5:1 的对比目标；状态标签同时包含文字。
- 320px 以上宽度可使用；桌面宽度优先优化为双栏信息布局。

## 验收与测试

1. 新增入口测试，先证明全局样式入口缺失，再导入 `styles.css` 并使其通过。
2. 保留并更新 App、库、搜索、收件箱与设置的行为测试；视觉重构不得破坏创建、选择、收藏、归档、恢复、导入和命令面板。
3. 运行前端单测、lint、typecheck、生产构建。
4. 启动桌面端并截图检查：样式加载、空库、含提示词库、详情、搜索、收件箱和设置至少各一屏。

## 非目标

- 不引入账号、网络同步、第三方 UI 组件库、遥测或新的后端功能。
- 不为了演示添加伪造的统计或虚构提示词数据；空状态和真实本地数据均应良好工作。
