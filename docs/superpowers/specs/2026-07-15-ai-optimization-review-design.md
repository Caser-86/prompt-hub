# AI 优化与差异审核设计

## 范围

在提示词详情页提供 AI 优化入口。用户选择当前提示词、填写优化指令后，应用把原提示词正文作为受控输入提交给已配置的 OpenAI 兼容提供方。成功结果始终创建一条新的收件箱草稿；原提示词、其发布状态与历史版本均不改变。

## 数据与边界

优化请求复用既有凭据存储、HTTPS 限制、45 秒超时、限流与无效响应处理。草稿来源记录模型、生成时间及“由提示词 <id> 优化”的来源摘要；不记录 API Key。草稿正文和原文只在本地详情页以 React 文本节点显示，差异不解释或执行任何内容。

## 工作流

详情页的“AI 优化”打开内联表单。提交后显示进行中或可恢复错误状态，且保留用户填写的优化指令。成功后切换到新草稿的审核视图，显示原正文与候选正文的行级差异，并提供进入收件箱审核的链接。发布仍沿用现有发布校验与显式用户操作。

## 不在本次范围

不覆盖原提示词，不自动发布，不把 AI 输出写进历史版本，也不加入虚假的客户端取消。真正取消需要可中断的后台生成任务模型，作为独立改造处理。

## 真实取消任务模型

生成请求获得唯一任务 ID，并在后端以取消令牌注册。取消命令只接受该任务 ID；它中止尚在运行的 HTTP future，并在保存收件箱草稿前再次检查令牌。取消结果不得创建或修改任何提示词。UI 仅在后端确认取消后解除进行中状态，保留用户填写的指令和输入摘要。

## 验证

测试必须证明优化命令仅创建收件箱草稿、保留来源关联与模型摘要、失败时不修改已发布提示词或表单内容、差异文本不会执行 HTML。既有生成、发布与版本历史回归测试必须通过。
