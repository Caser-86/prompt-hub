# Prompt Hub 正式产品规格

> 状态：产品基线  
> 产品定位：本地优先、可离线使用的桌面提示词资产管理与 AI 工具集成产品。  
> 本文是首发版本的唯一需求基线；任何新增范围都必须先更新本文并评估对发布计划的影响。

## 1. 目标与非目标

### 1.1 产品目标

Prompt Hub 帮助个人用户把分散在文件、网页和 AI 工作流中的提示词，转变为可追溯、可检索、可验证、可复用的本地资产。用户能够在桌面端手动使用提示词，也能让 Codex 等 MCP 客户端安全地调用同一个本地提示词库。

首发版本必须做到：

- 在离线状态下管理私有提示词并快速查询。
- 完整记录提示词的来源、时间、适用工具/模型和有效性。
- 安全导入、审核、去重、版本化、备份和恢复。
- 通过本地 MCP 提供受控的读操作和“仅写入收件箱”的草稿操作。
- 交付可安装、可升级、可诊断的 Windows 桌面应用。

### 1.2 非目标

- 首发不提供账号、云同步、团队协作或公开社区。
- 首发不自动抓取所有网页或未经授权地读取第三方 AI 对话历史。
- 首发不将 AI 生成内容自动发布到正式提示词库。
- 首发不依赖向量数据库或自动模型评测；产品必须在无网络和无模型密钥时保持核心可用。

## 2. 用户与关键工作流

### 2.1 用户角色

- **库拥有者**：唯一的本地数据拥有者，管理提示词、模型连接、备份和 MCP 授权。
- **MCP 客户端**：如 Codex，只能通过显式提供的 MCP 工具访问当前用户的本地库。

### 2.2 首要工作流

1. 用户手动录入、导入文件或粘贴网页链接。
2. 系统将自动采集结果放入收件箱，保留原始来源和导入记录。
3. 用户审核内容，补全分类、标签、适用工具/模型和有效性后发布到本地库。
4. 用户通过搜索和筛选定位提示词，填充变量后复制或导出。
5. Codex 通过 MCP 搜索或读取已发布提示词；提交的新内容只能进入收件箱。
6. 用户根据真实使用结果标记有效性、评分和复测时间；所有编辑形成可恢复版本。

## 3. 数据模型与数据治理

### 3.1 提示词记录

每条提示词至少包含以下字段：

| 领域 | 字段 |
| --- | --- |
| 身份与内容 | UUID、标题、正文、用途说明、分类、标签、收藏状态 |
| 模板 | 变量名称、类型、说明、默认值、是否必填、渲染示例 |
| 来源 | 来源类型、来源名称、URL 或本地位置、原始摘录、收集时间、导入任务 ID |
| 时间 | 创建时间、最后编辑时间、导入时间、最后验证时间、归档/删除时间 |
| 兼容性 | 适用工具、适用模型、兼容性说明、最后确认时间 |
| 有效性 | `未验证`、`有效`、`失效`、`待复测`；人工评分、验证备注、验证人（本地用户） |
| 生命周期 | 收件箱、已发布、归档、软删除；当前版本号 |

来源必须是独立记录而非单一文本字段：一条提示词可保留多个来源，来源记录不可因编辑正文而丢失。

### 3.2 版本与审计

- 正文、变量、元数据、有效性和兼容性变更均记录版本快照及变更时间。
- 恢复历史版本应生成新的最新版本，历史版本不可被覆盖。
- 软删除可恢复；永久清除仅从显式维护界面执行，并在备份策略允许时提示影响。
- 导入、AI 生成、MCP 草稿、发布、归档和恢复均写入本地审计事件。

### 3.3 数据质量规则

- 发布前要求标题、正文、至少一个分类或标签、来源类型和有效性初始状态。
- 基于规范化正文哈希识别完全重复；相似候选只作提示，不得自动合并。
- 失效提示词保留可检索性，但默认在普通搜索中降权，并显示失效原因和最后验证时间。
- 工具/模型兼容性允许“未知”；不得把未验证兼容性标为有效。

## 4. 功能规格

### 4.1 搜索、筛选与使用

- 使用本地 SQLite FTS5 三元索引检索标题、正文、说明、标签和变量说明；短关键词采用标题/标签回退查询。
- 支持关键词、短语、分类、标签、来源、时间范围、适用工具、模型、有效性、评分、收藏和生命周期筛选。
- 默认排序：文本相关度、有效性、评分、最后验证时间、更新时间；用户可切换为时间或评分排序。
- 结果卡显示命中片段、来源、模型、有效性、评分和更新时间；详情页可查看完整来源与版本历史。
- 渲染变量时必须校验必填字段、显示未替换变量并允许复制最终文本。

### 4.2 收件箱、导入与 URL 提取

- 支持手动录入、Markdown/TXT/JSON/CSV 文件导入、本地文件夹扫描、粘贴 URL。
- 文件扫描必须记录扫描路径、扫描时间、文件指纹和最后处理结果；同一文件的增量扫描不应反复创建重复记录。
- URL 提取需限制协议、重定向次数、响应大小和请求超时；禁止访问本机、内网及保留地址，防止 SSRF。
- 导入项必须在收件箱中展示提取内容、解析警告、重复提示和来源证据；用户明确发布前不得进入正式库。
- 导入失败提供可读错误、重试入口和可导出的诊断信息；单项失败不得回滚或破坏其他已导入内容。

### 4.3 AI 草稿

- 支持从需求生成完整提示词，以及优化已有提示词。
- AI 输出必须标记生成模型、生成时间、输入来源、请求摘要和可能的失败原因；不得记录 API Key 或不必要的敏感输入。
- 所有 AI 输出仅作为收件箱草稿；用户在差异预览中确认后才可发布。
- 模型提供方以可配置的 OpenAI 兼容接口接入；凭据只保存在系统安全存储，连接测试不写入提示词数据库。
- 无网络、无密钥、模型限流或模型响应无效时，必须保留当前编辑内容并给出可恢复错误状态。

### 4.4 MCP 与 Codex 集成

- MCP 使用本地 STDIO 传输，不开启网络服务端口。
- 提供 `search_prompts(query, filters, limit)`、`get_prompt(id)`、`render_prompt(id, variables)` 和 `save_prompt_draft(payload)`。
- 搜索结果默认只返回摘要与必要元数据；完整正文仅由 `get_prompt` 返回。
- `save_prompt_draft` 永远只能新建收件箱记录，不得修改已发布提示词或历史版本。
- MCP 响应应使用稳定、可版本化的 JSON Schema；错误至少区分参数错误、未找到、变量校验失败、权限/锁定、数据库不可用。
- 提供安装、启用、禁用、诊断和卸载说明；应用退出、数据库迁移或恢复备份时 MCP 必须给出明确不可用状态。

## 5. 安全、隐私与可靠性

### 5.1 安全和隐私

- 提示词库默认只保存在用户本机；不进行隐式遥测、上传或云同步。
- API Key 和可能的访问令牌使用操作系统安全存储；日志、崩溃报告和导出预览必须脱敏。
- URL 获取执行严格的出站请求策略，禁止本地网络访问和文件协议。
- 导入内容与模型输出一律视为不可信数据：界面渲染必须防止脚本执行，禁止将内容作为应用命令执行。
- 支持可选数据库加密与应用锁；若首发不启用，必须清楚说明本地磁盘访问风险。

### 5.2 备份、恢复和迁移

- 每次数据库迁移、恢复和永久清除前先创建带时间戳的备份。
- 支持用户选择备份目录、手动备份、保留策略、备份完整性校验和恢复预览。
- 恢复操作在替换当前数据前创建安全副本，并显示将恢复的版本和记录数量。
- 数据库迁移必须幂等、可测试，并在迁移失败时保持原库可恢复。

### 5.3 可观测性与支持

- 提供本地诊断页：应用版本、数据库版本、搜索索引状态、导入任务状态、MCP 状态与脱敏日志。
- 错误消息应说明用户可采取的下一步，而非只显示技术异常。
- 默认禁用外部遥测；若未来增加，必须采用显式同意和可撤销设置。

## 6. 发布质量门槛

### 6.1 测试

- 单元测试：数据校验、版本行为、有效性状态、变量渲染、去重、筛选和排序。
- 集成测试：数据库迁移、导入、收件箱发布、备份恢复、AI 失败回退、MCP 工具调用。
- 端到端测试：首次启动、创建/搜索/编辑/恢复/导出、MCP 配置后由真实客户端发现工具。
- 安全测试：URL 提取 SSRF 拦截、日志脱敏、API Key 不落库、不可信 Markdown/HTML 无脚本执行。
- 性能测试：使用中文提示词数据集验证常见查询、筛选和索引重建在目标硬件上的响应时间。

### 6.2 交付与升级

- 交付带版本号、签名和校验信息的 Windows 安装包；保留 macOS/Linux 构建路径。
- 每个发布版本提供变更说明、数据库兼容性说明和回滚/恢复说明。
- 自动更新必须在用户确认后执行，并在升级前自动备份。
- 首次启动引导必须说明数据位置、备份设置、MCP 安装方式和 AI 密钥的本地保存方式。

## 7. 分期与验收

### 首发版本

完成本地私有库、完整元数据、手动/文件/URL 导入、收件箱、版本与备份、全文检索、AI 草稿、MCP 和 Windows 安装包。

### 后续版本

浏览器扩展、经用户授权的会话采集、模型自动评测、云同步、团队空间和公开社区必须以独立规格进入计划，不能绕过首发质量门槛。

### 首发验收标准

只有同时满足下列条件，才可宣布首发完成：

1. 新用户可在 Windows 上安装并完成首次启动。
2. 用户可以离线创建、导入、审核、搜索、筛选、渲染、版本化和导出私有提示词。
3. 每条已发布提示词均能记录并展示来源、时间、适用工具/模型和人工有效性。
4. 用户可成功备份并恢复数据，迁移和失败场景有可验证保护。
5. Codex 可通过本地 MCP 搜索和读取提示词，且只能将新内容写入收件箱。
6. 自动化测试、端到端测试、安全测试和生产打包验证全部通过，并有可复现的验证记录。
