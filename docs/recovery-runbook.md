# 数据恢复运行手册

## 先决条件

- 关闭可能正在访问同一数据库的 Prompt Hub 与 MCP 客户端。
- 保留原数据库和所有备份；不要手工覆盖或删除文件。
- 在 Windows 使用受保护的本地目录，不要把数据库或备份放入公开共享目录。

## 恢复备份

1. 在“设置 → 备份与恢复”填写备份文件路径，选择“检查恢复内容”。
2. 仅在完整性校验通过后，确认架构版本、字节数与提示词数量。
3. 选择“确认恢复备份”。应用会先创建恢复前安全备份，再替换当前数据库。
4. 恢复完成后记下显示的安全备份路径；若内容不符合预期，可用这份安全备份重复上述流程。

损坏或非 SQLite 备份会在预览阶段被拒绝，不会开始恢复。

## 迁移失败或启动失败

数据库启动前若需升级，应用会在同目录创建 `*.pre-migration.*.bak` 完整性校验备份。保留该文件，并用受支持版本的 Prompt Hub 打开原数据库；不要删除原库再尝试。

如果诊断页显示搜索索引不一致，先使用“重建搜索索引”。该操作不替换提示词、版本或来源记录。

## 证据与限制

恢复预览、损坏备份拒绝、恢复前安全备份和迁移备份均有自动化测试。磁盘满、进程在文件替换瞬间终止、以及跨进程锁竞争尚未完成发布环境演练；遇到这些情况应保留全部文件并先复制数据目录后再排障。
